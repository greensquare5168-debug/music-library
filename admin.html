🔒 讓「站主才能改」變成真的（一次性設定）

下面這段貼到 Supabase 的 SQL Editor 執行一次，就建立「只有站主的 Email 能寫入」的規則。 之後就算別人改網頁，也動不了資料。

-- 內容表：所有人可讀，只有站主能改
create table if not exists site_content (
  id bigint generated by default as identity primary key,
  slug text unique not null,
  body text,
  updated_at timestamptz default now()
);

alter table site_content enable row level security;

create policy "read all" on site_content
  for select using (true);

create policy "owner insert" on site_content
  for insert to authenticated
  with check ((auth.jwt() ->> 'email') = 'greensquare5168@gmail.com');

create policy "owner update" on site_content
  for update to authenticated
  using ((auth.jwt() ->> 'email') = 'greensquare5168@gmail.com');

create policy "owner delete" on site_content
  for delete to authenticated
  using ((auth.jwt() ->> 'email') = 'greensquare5168@gmail.com');
⚠️ 網頁端（這頁）寫的角色判斷只能決定「看到什麼」，擋不住改網頁的人。 真正的權限一律要在資料庫用 RLS 控管 —— 上面這段就是。
